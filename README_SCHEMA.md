# Schema Configuration by Environment

This project supports multiple database providers (SQL Server for local development and PostgreSQL for production on Vercel).

## Configuration Files

- `schema.zmodel.local`: Configuration for local development with SQL Server
- `schema.zmodel.vercel`: Configuration for production on Vercel with PostgreSQL
- `schema.zmodel`: Main file (automatically generated based on environment)

## Automatic Scripts

The scripts in `package.json` automatically handle:

1. **`prebuild`**: Configures for Vercel (PostgreSQL)
   - Copies `schema.zmodel.vercel` → `schema.zmodel`
   - Processes all `.zmodel` files to remove `@db.UniqueIdentifier` and replace `@db.NVarChar(Max)` with `@db.Text`

2. **`prebuild:local`**: Configures for local development (SQL Server)
   - Copies `schema.zmodel.local` → `schema.zmodel`
   - Keeps `@db.UniqueIdentifier` in `.zmodel` files

3. **`predev`**: Configures for local development (SQL Server)
   - Same as `prebuild:local`

4. **`pregenerate`**: Configures for local generation (SQL Server)
   - Same as `prebuild:local`

## Processing Scripts

### `scripts/copy-schema.js`

Main script that:
1. Restores `.zmodel` files from git (original state with SQL Server)
2. Copies the correct schema (`local` or `vercel`)
3. Processes `.zmodel` files according to the provider

**Manual usage:**
```bash
node scripts/copy-schema.js local   # For SQL Server
node scripts/copy-schema.js vercel  # For PostgreSQL
```

### `scripts/process-schemas.js`

Script that processes `.zmodel` files in the `zmodel/` directory:

- **PostgreSQL**: 
  - Removes `@db.UniqueIdentifier` (not compatible with PostgreSQL)
  - Replaces `@db.NVarChar(Max)` with `@db.Text` (PostgreSQL equivalent)
- **SQL Server**: Keeps `@db.UniqueIdentifier` and `@db.NVarChar(Max)` (required for SQL Server)

**Manual usage:**
```bash
node scripts/process-schemas.js postgresql
node scripts/process-schemas.js sqlserver
```

## Provider Differences

### SQL Server
- Uses `@db.UniqueIdentifier` for UUID fields
- Uses `@db.VarChar(n)` for strings with specific length
- Uses `@db.NVarChar(Max)` for large text fields (JSON, etc.)

### PostgreSQL
- Does not use `@db.UniqueIdentifier` (uses `String @default(uuid())` directly)
- Uses `@db.VarChar(n)` in a compatible way
- Uses `@db.Text` instead of `@db.NVarChar(Max)` for large text fields
- Requires `directUrl` in the datasource for migrations

## Important Notes

1. **Do not edit `schema.zmodel` directly**: This file is automatically generated
2. **`.zmodel` files are temporarily modified**: They are restored from git before each processing
3. **Git must be available**: To restore files to their original state
4. **Changes to `.zmodel` must be committed**: For them to work correctly in both environments

## Recommended Workflow

### Local Development
```bash
npm run dev          # Automatically configures for SQL Server
npm run build:local  # Local build with SQL Server
```

### Production/Vercel
```bash
npm run build        # Automatically configures for PostgreSQL
```

## Troubleshooting

If you encounter errors related to `@db.UniqueIdentifier`:

1. Verify that `.zmodel` files are committed in git
2. Run manually: `node scripts/copy-schema.js [local|vercel]`
3. Verify that the main schema is copied correctly
